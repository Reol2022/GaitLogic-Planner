## 6. MySQL 环境说明

E2 的同一产品代码基线已经完成：

- MySQL `5.7.20-log`：645 passed，0 failed，1 个 Windows symlink skipped；
- MySQL `8.0.46`：645 passed，0 failed，1 个 Windows symlink skipped；
- 两个矩阵的随机测试数据库残留均为 0。

E3 运行时发现工作树 `.env` 的数据库地址指向远程主机。为避免在非本地环境创建和
删除随机数据库，本轮拒绝复用该配置，并以明确无权限的本机探测账号执行完整
pytest。因此 E3 的 66 个 skipped 是数据库环境隔离结果，不能描述为 E3 MySQL
矩阵重新通过。

E3 只修改版本声明、公开文档、脱敏 Smoke 报告和版本一致性测试，没有修改 ORM、
SQL、事务、迁移或数据库业务代码。结合 E2 双数据库矩阵证据与 E3 相关专项通过，
该环境限制不影响 v0.12.0 核心能力判断；正式发布操作前仍建议在明确的
`127.0.0.1` 隔离凭据下再次复跑矩阵。

## 8. 安全与仓库边界

- `.env.example` 中 Chat/Embedding Key 均为空，Provider 地址和模型不写真实值。
- Readiness 与 Smoke 只输出非敏感模式、状态、公开 document ID 和聚合计数。
- Smoke 不记录用户 Query、Prompt、Context、Tool Result、Excerpt 或 Provider 原文。
- 真实 Index 位于 Git 忽略的运行目录，不进入发行包，也不位于 Web Root。
- 文档未写入数据库密码、真实 API Key、本机绝对路径或私有索引 ID。
- 产品仓库与竞赛仓库隔离检查通过。
- 竞赛仓库 HEAD 保持
  `1f267d23857ad905c87ceee6e924da854343d1d9`，工作区保持干净。

## 9. 已知限制

- 当前为邀请制 Alpha；
- 知识库规模有限；
- 不构成医疗诊断；
- 无 Hybrid Retrieval 与 Reranker；
- 无长期记忆；
- 无自动训练计划修改；
- Provider 可能发生短暂故障；
- Quota 仍是进程内限制；
- 竞赛人工 Forbidden 标签复核和盲评尚未完成，不能将产品发布等同于竞赛验收。
