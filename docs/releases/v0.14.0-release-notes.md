# GaitLogic v0.14.0 Release Notes

v0.14.0 is an Agent productionization release. It adds safe request lifecycle tracing, optional OpenTelemetry export, bounded runtime metrics, a unified Provider Failure Taxonomy, and a public fictional regression suite without adding a new training decision or plan-write capability.

## Included

- Trace/Span coverage for Coach, Tool, RAG, Provider, Validator, Fallback, LangGraph, HITL, transaction, and plan versioning paths.
- Optional OTLP Trace Sink behind the internal observability abstraction.
- Low-cardinality runtime metrics for request, Tool, RAG, Provider, Validator, Fallback, Weekly Review, and approval outcomes; latency P50/P95 uses bounded in-memory samples.
- Bounded timeout/connection/429/5xx retry with safe failure classification for Chat and Embedding providers.
- Unified Coach, RAG, Retrieval, and Weekly Adaptive offline regression command: `python scripts/evaluate_agent.py --suite all`.

## Verification status

Coach, RAG, and Weekly Adaptive suites pass. Retrieval retains its public baseline 17 failures; the honest overall status is `PARTIAL`, with no regression or safety gate failure. Runtime metrics and trace data exclude prompts, user queries, identities, raw model responses, vectors, and credentials.

## Upgrade

No database migration is required. Deploy code and frontend together, then run Python compilation, `pytest -q`, the unified evaluation, frontend typecheck/tests/build, and public-boundary checks. Optional observability remains disabled unless explicitly enabled through environment configuration.

## Known limits

The built-in Metrics Sink is bounded, in-process aggregation rather than a durable time-series backend. No RAG expansion, write tools, automatic plan changes, long-term memory, multi-Agent execution, or medical diagnosis capability is added.
