# GaitLogic v0.13.0 Release Notes

v0.13.0 introduces deterministic Weekly Facts and an adaptive coaching loop. The release keeps plans and workout logs as separate sources, uses LangGraph for weekly-review orchestration and human interruption/resume, and applies a plan change only after authenticated approval and server-side revalidation.

## Included

- Weekly planned/actual facts, deviations, data quality, warnings and stable hashes.
- LangGraph rules, RAG, generation, validation, fallback and finalization nodes.
- Inspectable Plan Adjustment Proposal before/after diffs.
- Persistent SQLAlchemy/MySQL checkpoints for approval workflows.
- Plan versions, idempotent apply, immutable audit history and controlled rollback.
- Safe workflow tracing and an adaptive weekly-review Vue page.
- A 32-case deterministic public evaluation using fictional data.

## Upgrade

Back up the database, validate upgrade and downgrade in an isolated MySQL environment, then run `scripts/upgrade_v0130_adaptive_plan.py` according to `docs/DEPLOYMENT.md`. Rebuild the frontend and run the complete backend and frontend suites before routing production traffic.

## Safety boundaries

The LLM does not receive a general plan-write tool. RAG cannot override canonical facts or deterministic rules. Rejected proposals do not update plans, repeated approval is idempotent, and public APIs derive user identity from authentication. This release is not a medical diagnosis system.

## Known limits

Proposal edit is not exposed in v0.13.0. The tracing layer is prepared for a later OpenTelemetry adapter but does not ship a full telemetry platform. Persistent checkpoint and migration verification still requires an isolated MySQL 5.7/8 environment with database-creation permission.
