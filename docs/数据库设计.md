# 数据库设计

## 基础要求

- 数据库名：`gaitlogic_planner`
- MySQL：8.0+
- 字符集：`utf8mb4`
- 默认排序规则：`utf8mb4_unicode_ci`
- 表引擎：`InnoDB`
- 主键：`BIGINT AUTO_INCREMENT`
- 所有核心表包含 `created_at` 和 `updated_at`
- `updated_at` 自动更新
- 不使用 SQLite
- 不引入 Alembic

## 表设计

### training_cycles

训练周期表，对应一个完整训练阶段，例如 `2026夏训`。保存周期目标、目标比赛和周期说明。

### training_blocks

训练块表。既可表示标准周，例如 `Week 1`，也可表示 `6月最后两天` 这样的非标准训练块。`sort_order` 必须存在，用于保证训练块顺序。

### planned_workouts

计划训练课表，对应 Excel `计划索引` Sheet。保存日期、星期、月份、阶段、训练内容、重点说明、计划距离、原始主类型、归一化主类型和来源行信息。

### workout_logs

训练日志表，对应 Excel `训练日志` Sheet。与计划训练课一对一，保存完成状态、实际距离、配速、心率、RPE、有效训练量、身体状态、疼痛信息和复盘调整。

### block_reviews

训练块复盘表，对应 Excel `每周复盘` Sheet。虽然 Excel 名称是每周复盘，但数据库使用块级复盘，以兼容非标准周块。

### pace_rules

配速规则表，对应 Excel `配速与规则` Sheet 中的配速参照表。保存 `R`、`I`、`T2`、`T1`、`M`、`E`、`REC`、`LSD` 等规则。

### excel_import_jobs

Excel 导入任务表。当前只记录导入任务状态、文件信息和统计结果，不实现 Excel 解析。

## 关系

- `TrainingCycle` 一对多 `TrainingBlock`
- `TrainingCycle` 一对多 `PlannedWorkout`
- `TrainingBlock` 一对多 `PlannedWorkout`
- `PlannedWorkout` 一对一 `WorkoutLog`
- `TrainingBlock` 一对一 `BlockReview`
- 删除 `TrainingCycle` 时级联删除 `TrainingBlock` 和 `PlannedWorkout`
- 删除 `TrainingBlock` 时级联删除 `PlannedWorkout` 和 `BlockReview`
- 删除 `PlannedWorkout` 时级联删除 `WorkoutLog`

## 约束和索引

- `training_blocks`: `cycle_id + sort_order` 唯一
- `planned_workouts`: `cycle_id + workout_date` 唯一
- `workout_logs`: `planned_workout_id` 唯一
- `block_reviews`: `block_id` 唯一
- `pace_rules`: `code` 唯一
- `excel_import_jobs`: `file_hash` 索引
- `planned_workouts`: `workout_date` 索引
- `planned_workouts`: `main_type_normalized` 索引
- `workout_logs`: `status_normalized` 索引
- `training_blocks`: `start_date, end_date` 联合索引
