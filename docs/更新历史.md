## v0.10.3 - Runner State 与 Garmin 自动状态闭环

### 新增

- 新增 Runner State 当前状态模型，按自然日窗口聚合最近 7 天、28 天训练距离、时长、次数、完成率、RPE、心率覆盖和强度相关指标。
- 新增确定性状态推断，以版本化规则输出跑量趋势、训练一致性、疲劳状态、训练阶段、风险提示、Reason Code、Evidence、证据覆盖程度和数据质量；数据不足时明确返回 `UNKNOWN`。
- 新增“训练状态”页面，展示当前状态、核心指标、风险提示、Evidence、skipped signals、数据质量和非医疗声明。
- 新增手动历史快照、历史列表、Timeline、趋势和详情；旧快照保留保存时的规则版本、Evidence 和限制，不以新规则重新计算。
- 新增 Garmin 同步 Material Change 判断、稳定 `sync_run_id` 和同步结果契约，只在影响 Runner State 的训练事实发生有效变化时进入自动快照流程。
- 新增 Garmin 自动状态快照、触发回执、处理租约恢复和幂等控制；同一逻辑同步的 retry Job 共享回执结果。
- 新增同步页面自动快照结果反馈，区分创建、重复内容、无有效变化、未提交和非阻塞失败。

### 改进

- Garmin BackgroundTask 和轮询 Worker 统一通过 `ActivitySyncPipeline` 执行，Pipeline 是自动快照唯一接入点。
- Garmin 同步使用 Session A，Runner State 自动快照使用独立 Session B；快照失败不会回滚同步事务，也不会改变同步 Job 终态。
- 同步任务详情按当前用户装配回执；列表采用批量查询，避免逐任务加载造成 N+1。
- FastAPI 0.139 路由树结构测试改为基于 OpenAPI 公共契约，不依赖 `_IncludedRouter` 等内部结构。
- Windows 新环境增加 `tzdata` 条件依赖，保持 `Asia/Shanghai` 时区语义。
- setuptools 改用显式包发现，只发布 `planner_core*` 和 `server*`，保留 namespace package 支持并排除前端、SQL、文档和根目录资源。
- 修复 `TrainingRuleHit.evaluation_id` 重复索引定义，以及训练日历、Usage Event、Workout Import 的集成测试 Fixture 和验证预期。

### 安全与边界

- 大语言模型不参与 Runner State 指标计算或状态推断；规则保持确定性、可追溯和可解释。
- Runner State 不构成医疗诊断，不推断伤病概率，不自动生成或修改正式训练计划。
- 自动快照的用户、触发类型、触发引用、规则版本、payload 和哈希均由服务端确定，客户端不能伪造。
- 公共接口不暴露 Garmin Token、API Key、数据库凭据、真实训练 payload、回执内部租约字段或用户身份映射。
- 产品公共仓库继续与竞赛私有仓库隔离；真实用户状态、内测统计、竞赛结果和私有策略不进入公共仓库。

### 兼容性与测试

- 支持 Python 3.11；FastAPI 0.139 路由注册和实际请求均通过 OpenAPI/TestClient 回归。
- Windows 全新 Python 3.11 环境已验证正常 editable install、`tzdata` 自动安装、包/ORM/FastAPI 导入和 OpenAPI 路径。
- 已验证带构建隔离与不带构建隔离的 `pip install -e .`；wheel/sdist 可构建，wheel 仅包含 `planner_core`、`server` 和发行元数据。
- 后端测试覆盖 Runner State、历史快照、Garmin Material Change、触发回执、Pipeline、权限、去重、并发和失败隔离；前端测试覆盖当前状态、历史趋势、详情和同步结果提示。
- 迁移脚本保持 MySQL 5.7/8 兼容设计；正式部署仍应在目标 MySQL 版本的隔离环境完成迁移链和回滚复核，不以跳过项代替双版本验证。

### 当前限制

- 当前不会自动生成或修改训练计划，也没有上线 Coach Agent。
- 自动快照目前只接入 Garmin Provider；每日定时、计划调整和其他 Provider 尚未接入。
- `FAILED_NON_BLOCKING` 只表示状态历史暂未更新，不改变 Garmin 同步主结果。
- 独立 wheel 暂不携带仓库根目录的 `config` 和 `knowledge` 资源；wheel-only 部署需要后续资源打包与定位方案。

## v0.10.2 - 科学规则治理与验证版

### Added

- 新增科学证据来源、规则与证据关联、规则适用范围、阈值声明、规则版本历史、生命周期、审核、发布、回滚和审计日志。
- 新增规则测试案例、测试运行、回归验证、测试覆盖率、规则影响分析、冲突诊断和运行质量聚合统计。
- 新增 `scripts/migrate_training_rules_to_governance.py`，可将 v0.10.0/v0.10.1 旧规则迁移为治理版本，并生成基础证据、关联和人工确认测试模板。
- 新增 `scripts/validate_training_rules.py`、`scripts/run_training_rule_tests.py` 和 `scripts/run_training_rule_regression.py`。
- 后台新增“科学规则治理”页面，展示证据来源、覆盖率、回归运行和运行质量。

### Boundaries

- 未发布规则不参与正式评估。
- 未审核或测试失败的规则不能发布。
- 回滚不删除新版本，也不改变历史评估。
- 证据等级是 GaitLogic 内部治理分类，不等同于医学正式循证分级。
- 产品阈值只用于触发训练管理提醒或用户重新确认，不代表临床诊断阈值。

## v0.10.1 - 科学规则闭环接入版

### Added

- 新增统一训练事实构建层，计划、今日训练、训练后复盘和周复盘都先标准化 facts，再调用 v0.10.0 规则引擎。
- 新增计划安全校验服务，AI 计划草稿、Excel 导入草稿、正式训练计划和手动计划应用前均可复用同一校验流程。
- 新增今日训练规则评估接口和前端建议卡片，展示结构化 action、数据有限提示、命中规则和重新评估入口。
- 新增训练后规则复盘和周复盘规则评估，周复盘可生成结构化下周调整草稿。
- 新增 `training_adjustment_drafts`，调整草稿保留来源评估、原计划快照、状态和应用结果。
- 评估记录新增 facts hash、source version、过期标记和过期原因，为重复评估复用和计划变更后失效提供基础。
- 新增 v0.10.1 计划、今日、训练后和周复盘规则。

### Boundaries

- 调整草稿不会直接修改正式计划，必须由用户确认后才能应用。
- blocking 结果阻止自动应用，high 结果要求用户二次确认。
- AI 仅可润色结构化结果，不可覆盖规则最终 action，也不可输出医疗诊断。

## v0.10.0 - Training knowledge model and scientific rule infrastructure

### Added

- Added versioned training knowledge items, deterministic training rules, rule evaluation snapshots, and matched rule records.
- Added safe YAML/JSON loading, DSL validation, controlled condition operators, all/any/not logic, deterministic conflict resolution, and template explanations.
- Added `GET /api/training-knowledge/categories`, `GET /api/training-knowledge/items`, `GET /api/training-knowledge/items/{code}`.
- Added `GET /api/training-rules`, `GET /api/training-rules/{code}`, `POST /api/training-rules/evaluate`, `GET /api/training-rules/evaluations`, `GET /api/training-rules/evaluations/{id}`.
- Added admin endpoints for enabling rules, validating definitions, and syncing repository definitions to MySQL.

### Boundaries

- Rules return structured suggestions, review requirements, or block-auto-apply signals only.
- Rules do not modify official training plans, do not output injury probability, and do not provide medical diagnosis.

## v0.9.4 - 多平台运动数据同步框架与 Garmin 适配器迁移

### 新增

- 新增 `server/integrations/activity_sync` 通用同步框架，包含 `DataSyncFacade`、`ProviderRegistry`、`ActivitySyncPipeline`、provider capabilities、通用 schemas、稳定异常码和 worker 入口。
- 新增 Garmin provider adapter，并注册 `garmin` provider；新增 Mock provider，占位用于开发/测试，生产默认不开放。
- 新增通用数据同步 API：`/api/data-sync/providers`、`/connections`、`/connections/{provider_key}/connect|challenge|disconnect|sync`、`/sync-jobs`、`/activities`、`/reprocess|ignore|restore`。
- 新增前端“数据同步”页面 `/data-sync`，显示 provider 卡片、连接状态、能力和支持的同步模式；Garmin 详情页迁移到 `/data-sync/garmin`，旧 `/garmin-sync` 继续跳转兼容。
- 新增配置：`DATA_SYNC_ROLLOUT_MODE=inherit`、`DATA_SYNC_MOCK_PROVIDER_ENABLED=false`。
- 新增文档：Data Sync 架构、Provider Adapter 开发指南、Data Sync API、数据同步用户指南。

### 调整

- 旧 `/api/integrations/garmin/*` 接口保留响应兼容，但内部改为通过 `DataSyncFacade(provider_key="garmin")` 调用。
- 桌面侧边栏和移动端“我的”入口从“Garmin 同步”调整为“数据同步”。
- Garmin 同步架构文档补充 v0.9.4 迁移说明；Garmin 使用指南说明新入口和旧地址兼容。
- `DATA_SYNC_ROLLOUT_MODE=inherit` 默认继承 `GARMIN_SYNC_ROLLOUT_MODE`，避免已有灰度配置失效。

### 阶段 0 审计结论

- Garmin 专属且保留：登录/MFA、Garmin API 调用、Garmin 字段解析、Garmin 专属配置。
- 通用但原位于 Garmin 模块：连接状态、任务队列、活动落库、活动处理、自动导入开关。
- 已经通用无需迁移：`external_*` 数据表、`ProviderActivity`、`ProviderLap`。
- 高风险点：真实 Garmin 登录、token 加密、原始数据脱敏、活动自动导入、训练周期归属和幂等处理。

### 测试

- `python -m pytest tests\test_api_structure.py tests\test_data_sync_registry.py tests\test_garmin_sync_security.py tests\test_models.py -q`：14 passed, 9 skipped。
- `npm run build`：通过；仍有当前 Node/npm 版本提示、Rollup 注释提示和大 chunk 提示。

### 当前限制

- v0.9.4 先完成入口和框架迁移，Garmin 活动处理核心仍委托现有 Garmin service，后续再逐步下沉到通用 processing service。
- Mock provider 生产默认禁用。
- 真实 Garmin 登录仍受 Garmin SSO、账号区域、MFA 和限流策略影响。

## v0.9.3 - Garmin 多用户同步与训练数据标准化

### 移动端适配

- AI 计划历史草稿表、配速历史档案表移除过宽/固定操作列，移动端按钮可正常显示并支持横向滚动。
- 训练统计顶部指标卡在移动端改为两列紧凑布局，执行摘要表增加横向滚动。
- 从“我的”进入的功能页面支持左侧右滑返回“我的”页。
- 全局 Element Plus 表格补充移动端横向滚动、紧凑单元格和操作按钮不压缩样式。
- 列表中的英文枚举状态统一转为中文显示，覆盖 AI 草稿、Garmin 同步任务、Garmin 活动处理状态和同步模式。

### 新增

- 新增 Garmin 连接状态、连接、MFA 入口、断开连接、手动同步、任务查询、任务重试和活动处理 API。
- 新增 `/garmin-sync` 前端页面，支持连接状态、手动同步、任务列表和已同步活动列表。
- 新增 `external_account_connection`、`external_sync_job`、`external_activity_raw`、`external_activity`、`external_activity_lap`、`workout_log_external_activity`、`external_activity_resolution`。
- 新增 `ActivityProvider` 抽象、基于 `garminconnect/garth` 的 Garmin Provider 和 Mock Provider。
- 新增 AES-256-GCM 令牌加密服务，支持随机 nonce、key version、错钥失败和篡改失败。
- 新增 `python -m server.workers.external_sync_worker` 数据库队列 Worker。
- 新增 `python -m server.scripts.cleanup_external_activity_raw --dry-run` 原始数据清理命令。
- 新增 `GARMIN_SYNC_ROLLOUT_MODE=off|allowlist|all` 灰度开关，功能键为 `garmin_sync`。

### 调整

- 周期生命周期修复：训练周期新增 `draft`、`active`、`completed`、`archived` 状态，同一用户最多只能有一个 `active` 周期。
- 新建训练周期默认保持 `draft`，不再自动成为当前周期；启用周期必须走生命周期接口。
- 新增周期生命周期 API：`GET /api/training-cycles/active`、`GET /api/training-cycles/history`、`POST /api/training-cycles/{cycle_id}/activate`、`complete`、`archive`。
- 启用新周期时会事务化结束旧 active 周期，并将旧周期未来未完成计划标记为 `superseded`，保留已完成日志、Garmin 关联和复盘数据。
- 计划、日历和训练统计默认读取 active 周期；没有 active 周期时不再自动选择最近草稿。
- Garmin 计划外活动新增周期归属规则：优先继承计划/日志周期，否则按活动日期匹配 active/completed 周期；无候选为 `unassigned`，多候选为 `needs_review`。
- 新增周期审计命令：`python -m server.scripts.audit_training_cycles --dry-run`。
- Garmin 第二阶段闭环：活动同步后不再只显示状态，而是通过 `WorkoutLog`、`PlannedWorkout` 和 `workout_log_external_activity` 形成训练完成闭环。
- `ExternalActivity` 新增 `resolution_status`、`apply_status` 和 `composite_session_key`，拆分解析状态与写入状态。
- `WorkoutLog` 新增 `subjective_status`，支持“客观数据已同步、主观反馈待补充”的状态表达。
- Garmin 同日唯一计划的连续活动可合并到同一训练日志；计划外连续活动可按时间间隔合并为一堂计划外训练。
- 新增 Garmin 活动重处理 API：`POST /api/integrations/garmin/activities/reconcile`。
- 新增命令：`python -m server.scripts.reconcile_garmin_activities --user-id=<id> --start-date=<date> --end-date=<date> --dry-run`。
- 新增训练完成上下文接口：`GET /api/planned-workouts/{workout_id}/completion-context`。
- 同步只由用户手动触发，页面打开不会请求 Garmin。
- 手动同步接口在创建任务后会自动安排一次后台执行，避免本地或单进程部署忘记启动 Worker 后任务长期停留在 `queued`。
- Garmin 同步页面会自动轮询刷新 `queued` / `running` 任务，失败或部分成功任务支持一键重试。
- 单条 Garmin 活动处理失败时会隔离失败活动并写入任务错误摘要，避免整批同步状态不清晰。
- Garmin 同步页顶部按钮改为“刷新任务”，点击后明确刷新同步任务和已同步活动列表。
- Garmin 同步页新增“同步后自动导入训练计划”开关，默认开启；关闭后仅保存 Garmin 活动，不自动写入训练日志或关联计划。
- Garmin 圈数据写入前会修正重复 `lap_index`，降低因 Garmin 分段数据重复导致任务长期 `partially_succeeded` 的概率。
