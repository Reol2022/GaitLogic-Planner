# v0.13.0 架构复习

## 1. 解决的问题

v0.13.0 把“记录训练”推进到“基于一周事实提出调整、由用户批准后生成新计划版本”。它不让模型直接写课表，而是把事实、规则、知识、语言生成、人工授权和事务写入分层。

```text
PlannedWorkout + WorkoutLog + RunnerState
                |
                v
        Canonical Weekly Facts
                |
                v
       Deterministic Rules
                |
       +--------+---------+
       |                  |
       v                  v
 Training Knowledge   LLM Explanation
       |                  |
       +--------+---------+
                v
        Validator / Fallback
                |
                v
       Plan Adjustment Proposal
                |
          LangGraph interrupt
                |
          Human approve/reject
                |
                v
 Server revalidation + transaction
                |
                v
 New plan version + audit + rollback
```

## 2. 为什么这样设计

跑量、完成率和偏差是可计算事实，不应交给概率模型。训练知识可以帮助解释，但不能覆盖规则。计划写入具有真实后果，因此授权来自当前登录用户，最终写入由服务端重新校验并在单事务内完成。

## 3. 请求链路

前端 `/adaptive-weekly-review` 调用 `web/src/api/adaptivePlan.ts`。后端 `server/api/routes/weekly_reviews.py` 从认证上下文注入用户，`WeeklyFactsService` 查询一周数据，`build_weekly_review_graph()` 编排复盘。Proposal 通过 `AdaptivePlanApprovalService` 执行批准或拒绝，版本查询与回滚由 `AdaptivePlanVersionService` 完成。

## 4. 核心结构

- `WeeklyFacts`：只包含可追溯事实、规则结果、质量与限制。
- `WeeklyReviewState`：图内部状态，包含内部 user_id，但公共 `WeeklyReviewResult` 不包含。
- `PlanAdjustmentProposal`：只读候选变更，保存 before/after、reason 和 rule evidence。
- `AdaptivePlanVersionRecord`：每次应用或回滚形成的新审计版本。
- `SpanRecord`：安全的节点耗时、状态与错误码记录。

## 5. 边界情况

缺失距离保留为 `None`，不冒充 0；无计划时完成率不伪造；高疲劳不能增加距离或强度；锁定和已完成训练不能被提案修改；重复批准只返回已存在版本；回滚创建新版本而不删除历史。

## 6. 测试

领域测试集中在 `tests/test_weekly_facts_domain.py`、`tests/test_adaptive_plan_proposal_service.py`；图测试在 `tests/test_weekly_review_graph.py`；数据库与权限测试在 `tests/test_adaptive_plan_hitl.py`；前端组件测试位于 `web/src/components/weekly-review/`。

## 7. 面试怎么讲

先讲安全边界：确定性事实和规则掌握决策权，LLM 只解释，用户批准后服务端再校验。再讲工程闭环：LangGraph 负责有状态编排和暂停恢复，SQLAlchemy 事务负责原子写入，版本表负责审计与回滚，Trace 负责定位降级点。

## 8. 追问

如果模型不可用，图走 Fallback，事实和 warning 仍保留；如果进程重启，SQLAlchemy checkpointer 可按 thread_id 恢复；如果重复点击批准，行锁、状态和已有版本共同保证幂等。
