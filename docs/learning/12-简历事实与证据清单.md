## 推荐的简历表述

- 设计并实现基于 FastAPI、SQLAlchemy 2.x 与 MySQL 的跑者训练管理系统，覆盖训练周期、计划、日志、恢复与多用户数据隔离。
- 构建可解释 Runner State 与 Garmin 同步后置快照链路，通过 Material Change、幂等任务标识和独立事务降低重复处理与失败耦合风险。
- 实现受限只读 Coach Agent：以严格 Tool Schema 提供训练事实，使用结构化输出、确定性 Validator 与 Fallback 保证建议不直接改写训练计划。
- 建立 32 条虚构场景的离线 Agent Evaluation，检查工具召回、决策一致性、警告保留和越权声明。

## 简历审计结论

### 可以直接使用的项目描述

> GaitLogic Planner：面向严肃跑者的训练管理系统。基于 FastAPI、SQLAlchemy 2.x、MySQL 与 Vue 3 构建训练周期、计划、日志、恢复、Runner State 和 Garmin 同步闭环；实现受限只读 Coach Agent，以结构化 Tool Calling、确定性 Validator 和 Fallback 提供可解释训练建议。

这段描述对应已发布 v0.11.0；不包含未发布 RAG B，也没有承诺医疗诊断、自动改计划或真实业务指标。

### 可拆成的四条项目 Bullet

1. 设计训练周期、训练块、每日计划与训练日志领域模型，使用用户外键、复合索引和唯一约束支撑多用户隔离、同日多练与计划外训练记录。
2. 构建 Garmin 同步 Pipeline，以 `idempotency_key`、`sync_run_id`、活动唯一约束和 Material Change 处理重试/去重；通过 Session A/B 隔离保证自动快照失败不回滚已提交训练事实。
3. 实现 Runner State：基于 7/28 天训练窗口、完成率、RPE/心率覆盖和强度分类生成可解释状态、Evidence 与历史快照，保持医学结论和自动计划调整为禁区。
4. 实现只读 Coach Agent：八个受控训练工具经 Pydantic Schema 校验，模型输出再经确定性 Validator、Evidence ID 协议与 Fallback 约束；构建 32 条虚构离线评测案例验证工具/决策/限制一致性。
