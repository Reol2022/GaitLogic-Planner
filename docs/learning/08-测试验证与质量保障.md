## Agent Evaluation 的真实边界

v0.11.0 提供 32 条固定日期、完全虚构的离线案例。报告中的 12 项指标包括 Case Pass Rate、Intent Accuracy、Required Tool Recall、Forbidden Tool Call Rate、Tool Argument Validity、Decision/Planned Status Consistency、Warning/Limitation Retention、Fallback Success Rate、Unsupported Claim Rate 与 Rule Violation Rate。

它使用确定性 Mock Gateway，不访问网络、不读取真实 Key、不连接生产数据库，也不使用第二个 LLM 当裁判。因此它证明的是已定义场景上的系统契约，不证明真实用户满意度或开放域 Agent 能力。

## MySQL 验证

历史发布记录包含 MySQL 5.7 与 8 的隔离回归证据。本轮没有重新执行，因此当前学习文档不得把它表述为“本次已通过”。

MySQL 专项应覆盖：新库基线 Schema、升级/降级顺序、唯一约束竞争、JSON/日期/Decimal/索引/外键行为，以及随机测试数据库清理。

## 当前覆盖不足

- 没有仓库内 Docker/Compose 集成测试。
- 没有 Playwright 端到端浏览器测试资产证据。
- RAG B 尚未形成提交后的完整回归证据；RAG C/D/E 尚未开始。
- 缺少线上压测、慢查询、Worker 长时间运行、Garmin 真实 SSO 可用性指标。
- 需要持续检查测试 Fixture 是否因共享用户名、日期或 Session 污染而产生顺序依赖。

## 面试回答框架

不要说“测试覆盖率很高”而没有数字。应说明：我按风险分层测试，核心业务有服务/API 测试，外部 Provider 用 Fake/Mock，Agent 使用确定性评测集，发布前再跑隔离 MySQL、类型检查和构建；但 Docker、真实线上压测和 RAG 完整评测仍是缺口。
