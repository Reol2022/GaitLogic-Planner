# 06｜技术知识点学习笔记

本章不是百科。每个知识点都绑定当前项目的代码位置和应达到的掌握标准。

## FastAPI｜能修改

- 它解决什么：将 HTTP 路由、依赖注入、Pydantic 校验、OpenAPI 和异常响应组织为 API 服务。
- 项目位置：`server/main.py`、`server/api/routes/*`、`server/api/deps.py`、`server/common/exceptions.py`。
- 真实用法：`create_app()` 注册路由、CORS 与异常处理；Coach Route 通过 `Depends(get_current_user)` 注入当前用户；OpenAPI 是路由结构测试的公共契约。
- 常见错误：把 `app.routes` 私有结构当稳定 API；让客户端传 user_id；把业务错误和请求格式错误混为同一状态码。

## Pydantic 2｜能修改

- 项目位置：`server/schemas/*`、`server/agent/schemas.py`、`server/knowledge_retrieval/*_schemas.py`。
- 核心价值：请求/响应和 Agent Tool 输入输出都先经过结构校验，再进入业务代码。
- 实例：Provider 输出通过严格 Schema，TODAY 的模型输出与最终公共响应分离；未知 Evidence ID 不通过 materialize。
- 常见误区：把 `dict`、`Union` 或静默类型转换当“兼容”，掩盖 Provider 契约错误。

## SQLAlchemy 2.x 与 MySQL｜能解释并修改

- 项目位置：`planner_core/database/{base,session,models}.py`。
- 核心：同步 `SessionLocal`、ORM `Mapped` 类型、MySQL InnoDB、外键、唯一约束与索引。
- 重点：Session 生命周期不等于事务语义；服务层决定何时 commit/rollback。
- 面试追问：为什么复合索引常以 user_id 开头？为什么唯一约束是并发幂等的最终裁决？

## 训练业务建模｜能解释

- 项目位置：`TrainingCycle`、`TrainingBlock`、`PlannedWorkout`、`WorkoutLog`、`DailyRecoveryCheckin`。
- 核心：计划和实际分表；同日多练由 `session_index` 表达；计划外日志允许没有计划外键；缺失值不能视为 0。

## Garmin 同步、事务与幂等｜能解释

- 项目位置：`server/integrations/activity_sync/*`、`server/services/garmin_sync_service.py`。
- 核心：idempotency key、sync_run_id、外部活动 ID、payload hash、数据库唯一约束共同处理重试和去重。
- 关键取舍：Session A 提交训练事实后，Session B 再处理自动快照；B 失败不会回滚 A。
- 当前学习缺口：真实 Garmin SSO/MFA、DNS/TLS、限流策略和线上 Worker 监控。

## Agent Tool Calling｜能解释并修改

- 项目位置：`server/agent/{registry,orchestrator,tool,tools,validator}.py`。
- 核心：模型不是数据库权限主体；Tool Registry 按 Intent、只读属性、输入 Schema、输出 Schema 限制调用。
- 关键限制：最大模型调用次数、最大工具次数、同工具调用上限、上下文与答案长度上限。

## 结构化输出与 Provider Gateway｜能解释

- 项目位置：`server/agent/providers/openai_compatible.py`、`planner_core/config.py`。
- 核心：只允许受控 `thinking` 与 `response_format` 配置；不允许客户端指定 Provider、模型、Base URL、Key 或任意 extra body。
- 当前限制：不支持 reasoning_content 回放，也不支持 thinking 工具链。

## pytest、Vitest 与质量门槛｜能执行，需加强设计能力
