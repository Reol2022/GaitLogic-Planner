# v0.14 面试问答

**Metrics 和 Trace 区别？** Metrics 是聚合趋势，Trace 是一次请求路径。`server/observability/metrics.py` 从结束后的 Span 生成指标，`tracing.py` 负责父子 Span。

**P50/P95 是什么？为什么看 P95？** P50 是典型延迟，P95 反映尾部慢请求；Agent 常因 Provider 重试或检索异常出现少量极慢请求，平均值会掩盖问题。当前内存实现使用有界样本的 nearest-rank 分位数。

**为什么 trace_id 不能做 label？** 每次请求都不同，会产生高基数时间序列，耗尽监控后端资源，而且会把请求关联标识扩散到聚合系统。

**Provider success/retry/fallback 高说明什么？** Provider success 下降需查看 `failure_category`；retry 高通常是网络、429 或 5xx；fallback 高说明模型或下游依赖不稳定，但确定性结果仍应保持可用。

**模型升级后如何判断退化？** Runtime Metrics 看真实运行趋势，`scripts/evaluate_agent.py --suite all` 对固定虚构基线做离线回归；两者共同判断，不能互相替代。
