# v0.15.0 MCP Interview Guide

**30-second answer:** MCP standardizes how an external Host discovers and calls safe application capabilities. GaitLogic retains internal Tool Calling for its Agent, and adds MCP as a protocol adapter over the same Services.

**Follow-ups:** stdio is local process transport; Streamable HTTP is authenticated remote transport. Tools execute bounded actions, Resources expose stable public content, and Prompts are templates. Runner data stays in identity-scoped Tools rather than public Resources. Clients never supply `user_id`; the server validates a scoped token then injects identity. Origin validation reduces untrusted browser-origin access, and token passthrough would let a caller reuse credentials outside the intended boundary. MCP does not replace LangGraph, RAG, Rules or Validators.

Knowledge retrieval produces server-controlled canonical references rather than raw vectors, chunks or scores. The server is read-only because no write Tool, proposal action or commit path is exposed; any future write Tool requires separate intent, approval, transaction, versioning, audit and rollback design. Trace identifies transport/Tool/Resource failures without capturing content; the public offline Evaluation checks security gates. Current limits are no OAuth, no write Tools, no user-data Resources and no production trace backend.
