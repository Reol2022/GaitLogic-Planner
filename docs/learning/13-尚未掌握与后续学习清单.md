# 13｜尚未掌握与后续学习清单

## 不能写进简历的缺口

| 缺口 | 当前状态 | 学习/实现验收标准 |
| --- | --- | --- |
| Docker 与 Compose | 仓库无资产 | 可本地启动 MySQL、API、Worker、前端/Nginx；不含密钥；有 healthcheck |
| 云部署与 HTTPS | 无可核验生产配置 | 完成隔离云主机部署、证书、日志、备份、回滚演练记录 |

| RAG Evaluation | 规划中 | 固定检索集、Recall、引用正确性、冲突/降级与无依据声明测试 |

| 真实 Garmin 可靠性 | 外部依赖不稳定 | 建立认证/MFA/DNS/TLS/限流分类、重试与运营手册 |
| 异步任务生产化 | 有 Worker，但无队列证据 | 明确队列/锁/可观测性/崩溃恢复方案并验证 |

## 需要真正读懂的代码

1. `server/services/garmin_sync_service.py`：活动去重、匹配、复合训练与事务分支很多，应逐函数画图。
2. `server/services/runner_state_auto_snapshot_service.py`：租约、嵌套事务、并发回执和失败隔离。
3. `server/agent/orchestrator.py`：两次模型调用、工具调用限制、trace 和失败收敛。
4. `server/agent/providers/openai_compatible.py`：请求转换、安全 URL 校验、超时、重试与响应格式。
5. `server/knowledge_retrieval/index_service.py`：索引身份、原子写入、root hash 与派生文件边界。

## 建议学习顺序

### 第一阶段：能独立解释已发布能力

- 复述训练数据模型与三条核心调用链。
- 手写一次 Runner State 的窗口/缺失值/完成率规则测试。
- 用图解释 Garmin Session A/B 和 Job 幂等。
- 用 Mock Gateway 重跑 Agent Evaluation，并手动解释一个失败案例。

验收：不看文档能回答本章与第 11 章前十个问题。

### 第二阶段：完成 RAG B 的工程闭环

- 审查并提交 B 阶段代码。
- 重跑 B 专项、全量后端、前端和安全边界检查。
- 记录索引构建/查询的虚构 Demo，确认不泄漏 Key 或索引缓存。

验收：能解释 corpus root hash 与 index root hash 的差异，且 B 有独立提交和测试证据。

### 第三阶段：实现 RAG C/D/E

- 仅增加只读知识检索 Tool。
- 建立确定性 RAG Eval，不使用第二个 LLM 裁判。
- 在前端显示来源与限制，不能让知识内容覆盖 TODAY 决策。

验收：RAG 进入正式发布前，完成权限、引用、降级、冲突和公共边界测试。

### 第四阶段：部署与运维实战

- Docker/Compose 隔离环境。
- MySQL 备份/恢复与迁移演练。
- Nginx 502/504、Worker 卡住、Provider 503 故障演练。
- 形成脱敏运行手册与一次真实但不含私人数据的演练记录。

验收：可以从空环境部署、定位故障、回滚，并说明每一步的安全边界。
