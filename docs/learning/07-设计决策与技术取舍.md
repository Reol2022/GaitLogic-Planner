# 07｜设计决策与技术取舍

## 1. 确定性训练规则优先于 LLM

- 背景：训练状态、今日建议、风险提示涉及可追溯性和安全边界。
- 候选：让模型直接判断；全部规则化；规则决定边界、模型解释。
- 最终选择：Runner State、Readiness、TODAY decision 和 canonical Evidence 由确定性逻辑产生，LLM 只编排只读工具并解释。
- 优点：可测试、可复现、能在 Provider 不可用时降级。
- 缺点：规则维护成本高，表达灵活性较低。
- 风险控制：Pydantic Schema、Validator、Evidence ID 协议、Fallback。

## 2. 只读 Tool Calling，不给 Agent 写权限

- 背景：模型输出不稳定，训练计划是用户核心数据。
- 选择：当前 Registry 只注册 read-only 工具，客户端不传 user_id、Provider 或 Prompt。
- 优点：模型错误不会直接改课表；权限面小。
- 代价：无法做到“一键自动调整”。
- 后续：如引入写工具，必须采用显式草稿、用户确认、版本校验、事务审计和更严格评测，不能复用当前只读信任模型。

## 3. TODAY 事实与 Narrative 分离

- 背景：模型返回结构化字段时会出现类型错误、自由改写或无依据 Evidence。
- 最终选择：服务端 materialize 决策、数据质量、风险、warnings、limitations 和 Evidence；模型仅返回自然语言和 Evidence ID。
- 优点：公共 API 稳定，模型不能覆盖规则。
- 代价：内部 Schema 需要多一层转换。

## 4. Garmin Pipeline 作为自动快照唯一入口

- 背景：路由、BackgroundTask、Worker 如果各自调用自动快照，会产生重复触发和不一致行为。
- 最终选择：仅 `ActivitySyncPipeline.run_job` 在同步事务提交后调用自动快照服务。
- 优点：一次逻辑同步最多一次后置处理；Worker 与后台入口一致。
- 代价：Pipeline 成为关键编排点，需要专门测试。

## 5. Session A / Session B 隔离

- 背景：Garmin 同步事实与 Runner State 快照是不同可靠性等级。
- 最终选择：Session A 提交活动/日志；提交后新开 Session B 处理快照；B 失败返回非阻塞状态。
- 优点：快照问题不回滚训练事实。
- 风险：需要确保 A 已 commit，且 B 正确 rollback/close。

## 6. 内容哈希与数据库唯一约束共同去重

- 背景：手动保存、重试和并发会造成重复状态快照。
- 选择：canonical JSON + SHA-256 提供语义身份；数据库唯一约束提供并发最终裁决。
- 不选择：仅在内存中比对、仅依赖时间戳或 Python `hash()`。

## 7. RAG 先做 Corpus，再做 Retriever，再接 Agent

- 背景：直接接入向量搜索会混入来源、版权、版本和安全边界不清的内容。
- 选择：A 阶段先建立受控文档、来源、Chunk、Manifest root hash；B 阶段才做 Embedding/Vector/Retriever；C 阶段再接 Tool。
- 优点：可审计、可重复构建、引用可追溯。
- 代价：交付速度较慢；当前还没有完整 RAG 用户能力。

## 8. Exact Cosine Store 作为第一版检索存储

- 背景：需要先验证索引契约、过滤、引用和测试，而非先引入基础设施。
- 选择：B 阶段工作区采用本地 JSON 记录的 Exact Cosine Store。
- 优点：行为透明、无需外部服务、测试稳定。
- 缺点：不适合大规模向量、低延迟或并发检索。
- 后续：在 Retriever 契约稳定后替换为专用向量数据库。

## 9. 显式 setuptools 包发现

- 背景：根目录含 Python 包、文档、知识、脚本和前端。
- 选择：只打包 `planner_core` 与 `server`，排除其他目录。
- 风险：wheel-only 场景需要单独处理运行时知识/配置资源。

## 10. 先维护部署说明和脚本，Docker 化作为后续工作

- 当前证据：Nginx + Gunicorn/Uvicorn + Supervisor/Systemd 部署方案和 PowerShell SSH 脚本存在。
- 未选择的结论：不能因文档提到 Docker 就声称已 Docker 化。
- 后续决策门槛：先明确环境变量、静态资源、迁移、Worker、日志、健康检查和回滚，再设计 Dockerfile/Compose。
