# GaitLogic Planner v0.16.3

v0.16.3 consolidates the Garmin recovery, Partial Facts, DeepSeek Thinking, weekly planning, Evidence Reflect, approval, retrieval-evaluation, and release-diagnostics work into one formal release.

## User-visible value

1. **Training Knowledge Retrieval** — versioned running knowledge can be retrieved through Exact Dense, Qdrant, BM25, Hybrid RRF and optional reranking while preserving canonical citations.
2. **Garmin Unified Sync** — activity and daily recovery facts share one synchronization boundary; missing health metrics remain missing, manual recovery input keeps precedence, and partial provider failures do not erase successful activity imports.
3. **Partial Facts** — one absent optional signal no longer makes an otherwise answerable question unavailable.
4. **Decision Readiness** — readiness is evaluated by decision domain as READY, PARTIAL, BLOCKED or NOT_APPLICABLE with HARD, SOFT and CAPABILITY limitations.
5. **DeepSeek Thinking** — analytical Coach requests retain request-local reasoning across bounded tool rounds without exposing or persisting ordinary Coach reasoning.
6. **Weekly Review Analysis** — weekly facts, rules, readiness and knowledge evidence are condensed into a validated structured analysis.
7. **Plan Design** — planning is a second independent model request with its own thinking and output budget; raw Weekly reasoning is not forwarded.
8. **Evidence Judge and Reflect** — evidence sufficiency, conflicts and decision relevance are evaluated before a deterministic, bounded, white-listed reacquisition pass.
9. **Approval Checkpoints** — proposal approval state is integrated after Weekly Analysis and Plan Design, without weakening ownership, version, rules or transaction gates.
10. **Proposal Safety** — model analysis materializes through Python/Pydantic, deterministic validation, ownership checks, plan versions, HITL approval and server revalidation.
11. **MCP** — public MCP remains read-only and preserves identity, reference and prompt boundaries.
12. **Observability and Evaluation** — safe low-cardinality tracing and metrics cover Provider tasks and Reflect outcomes; Retrieval v1 and expanded-corpus v2 are reported independently.

## Provider and workflow behavior

- Task model profiles independently configure Coach fact queries, Coach analysis, Weekly Review Analysis, Plan Design and AI plan generation.
- Provider responses are classified by transport status, finish reason, empty content, JSON validity, schema validity and business validity, in that order.
- `finish_reason=length` is classified as output truncation. An empty final body with non-empty reasoning is identified as reasoning-output budget exhaustion rather than invalid JSON.
- Weekly Review Analysis and Plan Design use separate Provider requests, output budgets, retry state and trace spans.
- Plan Design consumes structured `WeeklyReviewAnalysis`; it never consumes raw Weekly reasoning.
- Structured materialization is deterministic Python/Pydantic. There is no third LLM call.

## Safety boundaries

- Raw Provider reasoning is internal diagnostic data, not a business fact or canonical evidence source.
- Raw reasoning is excluded from REST, MCP, frontend, traces, metrics, evaluation reports, RAG, rule evaluation and proposal validation.
- Weekly Review being PARTIAL never makes a plan proposal READY automatically.
- Plan application still requires deterministic validation, HITL approval, server revalidation, ownership, base-plan version, row locks, rules and a transaction.
- Coach agent state is request-local and is released at the end of the HTTP request; cross-request conversation memory is not introduced.

## Known limitations

- MySQL 5.7 runtime integration was not run; static compatibility checks are available.
- MySQL 8 integration requires an administrator-created isolated `gaitlogic_test` database. The application database is not used as a substitute.
- Retrieval v1 is the historical 12-document corpus baseline. It is retained and reproducible, but it is not the release gate for the expanded corpus.
- The current 52-document corpus uses Retrieval Evaluation v2. Eight audited queries remain retrieval improvement cases.
- Reflect is deterministic and defaults to one round, configurable from zero to two.
- Coach conversations do not provide long-term cross-request memory.
- The architecture does not use multi-agent execution.
- Raw Provider reasoning is internal diagnostic data and is not exposed publicly.
