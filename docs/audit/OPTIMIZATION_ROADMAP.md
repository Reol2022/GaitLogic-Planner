# 优化路线图：v1.1 / v1.2

本轮只审计，不自动开始以下实现。依据 [风险登记表](RISK_REGISTER.md) 和 [性能基线](PERFORMANCE_BASELINE.md)。无需预设 Redis、Celery、微服务或分库分表。

## v1.1 — 上线前安全收口（P0）

| 项目 | 为什么/证据 | 最小改动及模块 | 风险 | 验证标准 |
|---|---|---|---|---|
| 令牌信任域 | A-01，隔离 HTTP 证实 | Auth Service + deps + MCP 双向验证；设计旧 token 迁移 | 旧连接/登录可能失效 | Web/MCP/撤销/停用/管理员矩阵全部通过 |
| 异常日志最小化 | A-02，合成绑定值泄露复现 | engine hide_parameters、安全错误摘要、日志过滤 | 降低部分排错细节 | 多种异常 canary 不泄露，Trace 可关联 |
| Web 会话失效策略 | A-03，退出后 token 仍有效 | 复用 MySQL 会话版本或短 token + 可撤销刷新 | Schema 与客户端兼容 | 退出/改密/禁用/多端行为明确且实测 |
| 认证滥用门控 | A-04，代码无统一门控，边缘未知 | 登录/OAuth 入口有界窗口，可信代理来源和退避 | NAT 误伤 | 正常峰值可用，失败请求限流、无跨 Worker 绕过 |
| 上传解析预算 | A-05，读取及解析未统一有界 | 三个导入入口统一字节、ZIP、行列、时间预算；必要时只把解析移到受控线程 | 合法大模板被拒绝 | 标准模板全回归，安全极端样本快速拒绝 |

v1.1 完成门槛：无未接受的 High 身份/数据保密问题；故障日志脱敏；文件边界测试通过。针对候选风险先做安全复现，不把尚未确认的影响直接写成修复成果。

## v1.2 — 并发稳定性与可重复性能（P1）

1. **优先处理 P-01。** 用已有脚本复现并记录事件循环、线程池、连接池等待链；先最小化修改 MCP 同步身份查询执行方式和 Session 生命周期，再评估池大小/worker。不得通过放宽权限、关闭 scope 或只增加连接数获得好看的压测数字。
2. **统一成本配额。** A-06 使用短事务原子预占和幂等结算，不在模型网络等待期间持锁；独立验证失败退款、成功额度和总成本预算。
3. **依赖与发布可重复。** A-07 先按生产可达性筛选公告，分批升级；记录 Python/npm/运行产物摘要，重跑 OAuth、Garmin、Coach、导入和 Web 回归。
4. **补全尚未测量的业务性能。** 合成有效周期/正式计划/多活动/历史会话/草稿；分别测 Coach 固定 Fake Provider、AI Plan 生成+应用、恢复与自动同步调度混合负载。真实 Provider 只做单请求质量和延迟测试，不参加压力测试。

建议验收目标是待确认的 SLO，不是当前成绩：50 合成用户、至少 10 分钟持续混合负载，无池枯竭/永久停滞，超时和业务失败可见；撤压后 30 秒内恢复；纯本地只读请求 P95 < 1 秒、错误率 < 1%。若硬件预算不同，应先冻结环境和 SLO 再比较。

## P2 — 持续完善

| 方向 | 依据 | 最小方案 | 验证/注意事项 |
|---|---|---|---|
| SQL 扩展基线 | P-02，仅小数据 EXPLAIN | 扩到数年合成日志，测实际计划/关联表；比较优化前后结果与耗时 | 保持日期回退与跨用户语义，不盲目迁移 |
| 移动端首屏与产物 | P-03，构建已出现MB级分块 | 先测网络瀑布/Web Vitals，再按路由分割和压缩图片 | 不把构建体积直接当实测LCP，不只调整警告阈值 |
| 全对象权限矩阵 | 本轮仅抽查，不是全路由 BOLA 认证 | 对详情/导出/修改/删除/历史版本/Checkpoint 系统参数化 A/B 测试 | 覆盖所有可接收 ID 的路径和关联字段 |
| 可观测性 | 现有 SafeTracer/metrics 可复用 | event-loop lag、线程队列、DB checkout wait、超时/业务失败分开统计 | label 不含 user_id/token/query，原始异常不可随意导出 |
| 生产配置与恢复 | 本轮无生产访问 | 授权后只读核查 TLS/Nginx/DB grants/备份；恢复到独立库演练 | 不把备份存在等同恢复可用，不复制用户数据到公开测试 |
| AI/RAG 专项安全 | Prompt/Schema 控制不等于注入免疫 | 合成直接/间接注入、无答案、来源冲突、租户知识 ACL 测评 | 保留 HITL，不把模型 PASS 当业务成功 |

## 发布门禁

- 开发修复必须另行授权；当前候选工作树不自动集成或发布。
- 先在隔离 MySQL 复现/修复/回归，再评估兼容迁移与回滚。
- 在修复上线前，详细漏洞复现仅供私有审查；公开报告不能包含真实 token、内部地址、用户健康数据或密钥。
- 生产复核、扩大负载、真实 Provider 和备份恢复仍是独立验收项，不能被单元测试通过数替代。
