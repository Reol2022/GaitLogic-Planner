# 训练事实可靠性：第一阶段

状态：本地开发，未部署、未执行生产回填。基线：`74db603`，分支：`codex/training-facts-reliability`。

## 审计结论

- Garmin 分类汇总与逐圈明细混用：旧解析器在多个响应容器中取第一组列表，没有区分 `splitSummaries`、`typedSplits` 与 `lapDTOs`。分类汇总可以重叠，不能作为可累加的独立圈。
- 会话 RPE 遗留：单活动曾自动复制的 Garmin RPE，在会话增加关联活动后仍被保留。旧代码只标记“多活动需独立评价”，没有撤下失去作用域依据的旧值。
- 读取分支不一致：近期训练、负荷、Runner State、日历与复盘有多个直接读取 `log.rpe` 的入口，需要统一有效值策略。
- 实际与计划分类不同源：Runner State 之前优先采用计划类型，即使存在明确的实际类型。实际强度缺失时，计划类型也不能作为已验证的实际强度。

真实样本只用于授权的只读核查。报告和测试不保存真实训练记录、活动引用、分段成绩、健康指标或聊天正文。未发起 Garmin 请求，未修改生产数据库。

## 本轮变更

### RPE 作用域

- 新增 `effective_log_rpe`：自动 Garmin RPE 遇到多活动关联或明确的歧义元数据时不作为会话评价返回。
- 共享近期事实查询对需要核查的自动 RPE 执行一次批量关联数量查询，兼顾直接关联、关联表和旧活动引用；不为每条日志单独查询，不在读取时写回原字段。
- 同步重算时，自动活动 RPE 在会话变成多活动后失效；活动自己的评价仍保留。人工会话 RPE 和人工清空继续优先。
- 近期训练、MCP 详情、负荷计算、Runner State、周复盘、日历等读取使用同一有效值策略。活动复盘读取活动自己的 RPE，不将会话评分倒灌给某一活动。
- 无来源的历史值不再仅凭存在就宣称为人工会话评价；返回 UNKNOWN 来源/作用域。新逻辑不为缺失值填零。

### 原始圈与规范化分段

- 详情同步保留去敏后的原始分段载荷到既有私有 Raw JSON，递归移除凭据和 GPS 字段，不扩展公开原始数据访问能力。
- Provider 为分类汇总和明确的 lap DTO 标记不同来源，不猜测单位不明的时间偏移。
- `segments` 继续保留旧版“已存储圈”语义，以免破坏旧客户端；它不保证可累加。新增 `normalized_segments`、`segment_validation` 和 `activity_classification`。
- 规范化排除分类汇总；只按可靠身份或相同时间边界去重，不把距离相同的重复训练合并。
- 同标识但指标冲突，或存在时间重叠时，不任意选择一个表示。校验距离、时间及截断，缺失返回未知，不把列表返回完整等同于训练结构完整。
- 只有单个选定活动内、具有独立工作圈且距离和时间检查通过时，才输出结构性间歇识别及已有各圈。它不推断阈值区、VO2max 或个人相对强度。
- 用户自述的组数保留 USER_REPORTED_FACT 语义，仅作讨论上下文，不自动保存成 Garmin 已验证结构或正式计划。

### 状态解释边界

- 明确的实际训练类型优先于相冲突的计划类型；实际类型缺失时标记强度证据不足，不宣称已观测到全部实际强度。
- Runner State 增加“负荷风险不代表恢复许可”的限制，Coach 提示区分 LOW/NORMAL、恢复充分以及下一次强度建议。
- 没有调整原有风险阈值、Evidence 决策语义、HITL 或正式计划。

## 当前仍未完成

1. 仅有分类汇总的历史活动无法在本地还原独立圈。是否存在更多上游逐圈数据，需要单独的授权只读验证；修复不等于已恢复某次真实训练的全部组数。
2. 多活动整堂训练的结构确认界面与用户确认结构持久化尚未开发。复合、生理分区及训练目的分类不能仅靠平均配速、活动名称或总距离补造。
3. 尚未实现 Runner State v2 的分维度强度密度、赛事恢复和综合决策规则，也没有个人 HRV 滚动基线。第一阶段不能宣称四个 P0 均已解决。
4. 没有批量修正历史数据库 RPE、重建历史 Runner State、强制重同步 Garmin 或自动调整课表。后续回填需先预览差异并获授权。
5. 恢复字段缺失原因与数值时区 ID 的专项审计、每堂课结构化反馈及跨任务质量评测仍属后续工作。

## 后续顺序

先验证新的原始圈来源和多活动边界，再确认可用的训练结构。其后设计分维度负荷事实和恢复基线质量门控，审查决策规则，最后接入 Coach 与 Weekly Review。不能为使案例触发预期风险颜色而调整阈值。
