# AI 课表日期与生成校验修复

## 已确认的问题

- 页面按 `ceil(含首尾日期天数 / 7)` 推荐周数，却按完整周检查结束日，94 天推荐14周后又报超过赛事日期。
- System Prompt 的输出示例没有列出 Validator 要求的 `target_distance`，计划时长字段也未完整展示。
- 生成后所有校验直接失败，没有单独的格式恢复路径，页面主要依赖短暂弹窗反馈。
- 尚未取得本次内测失败任务的具体错误记录，不能认定每一个真实失败都由上述契约问题导致。

## 日期语义

- 一周从用户指定开始日期起连续计算7个自然日，不自行对齐星期一。
- 比赛位于最后一个训练周时，计划截止比赛当天，最后一周可不足7天。
- 开始日期到比赛日期含首尾94天，对应14个训练周，最后一周3天。
- 请求周数超过可容纳的训练周数时，生成前返回具体日期、可容纳周数和当前输入。
- 比赛晚于所选周期时允许生成阶段计划，明确说明未覆盖完整备赛周期。
- 后端上下文、Prompt、生成校验、草稿应用使用同一日历规则。前端按自然日计算，避免夏令时造成天数漂移。
- 不修改用户开始日期，不在比赛后补齐最后一周的课程。无需数据库迁移。

## 生成校验

- 服务端补齐缺失的、来自已确认请求的顶层目标和日期元数据。已有但冲突的值不覆盖，课程与训练量不自动改写。
- 统一 Prompt 输出契约，明确每周日期范围、目标距离、计划时长和最后一周范围。
- JSON 或 Schema 格式失败最多额外调用一次模型，第二次仍经过完整校验。
- 固定休息日、训练时长、禁用课型、跑量汇总、目标冲突和连续高强度等违规不走格式重试。
- 输出截断、空响应、格式错误和约束违规使用不同安全错误类别。页面持久显示可读原因。
- 不保存不合格的可应用草稿，不扣成功生成额度，不修改正式计划。
- 成功发生格式重试时合计真实返回的 Token Usage，未知用量不估算。
- 新缓存契约版本为 `2.0.1`，避免复用旧输出契约缓存。
- 日志仅记录失败类别、尝试次数、是否重试及周数，不记录 Prompt、模型正文或训练上下文。
