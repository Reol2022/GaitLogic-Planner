# MCP 训练事实与单次活动详情升级

日期：2026-11-09。基于 master `661dd6c`，分支 `codex/mcp-activity-facts-v3`。

## 审计与范围

现有服务端已注册六个只读工具，部分连接仍持有旧的四工具定义。本轮不增加同义工具，不改 OAuth 架构或 Garmin Provider，不生成计划、不触发同步、不写入正式训练记录。

确认的代码问题：Runner State 使用计划日期分窗，近期训练使用实际日期；前者还会丢弃被标为休息但确有正跑量的完成日志。详情接口将关联活动的 laps 拼到同一列表，且未投影已有的心率和动力学字段。未知来源被归类为 MANUAL，原始来源固定 UNKNOWN。

这些代码问题不能直接证明某条真实日志包含比赛、热身和放松，也不能证明某个具体跑量差额已经完全解释。本轮仅使用合成数据。

## 统计与来源

- 实际发生日期优先，仅缺失时回退计划日期；最近7/28天均为截至查询日的含首尾自然日窗口。
- 已完成且有正跑量的记录不会因为计划标成休息就消失；不自动把该记录改成恢复跑、长距离或比赛。
- 未知来源返回 UNKNOWN。日志的创建来源与字段声明的上游来源分开，来源声明不等于独立验证。手动 RPE、笔记不被改写。
- Runner State 对外增加7/28天窗口起止日期与日期依据。修正事实输入后，派生状态可能合理变化；训练规则阈值及 HITL 没有修改。
- 本轮统一的是完成记录的跑量与实际日期口径，不宣称所有统计同义。计划完成率仍以计划为分母；关键课数量仍受计划/记录分类差异影响，不能拿它当已验证的专项训练成绩。
- 历史已保存快照不被批量改写；验收比较应使用相同日期范围的新计算结果，不将旧快照与新查询直接比较。

## 单次详情：复用 get_training_detail

先查询日志：

```json
{"record_ref":"workout_log:123"}
```

响应保留日志汇总 `record`，同时提供独立设备活动列表 `activities`、`linked_activity_count` 和 `activities_complete`。最多返回20项活动摘要，完整数量单独给出。

多活动时 `selection_required=true`，不自动选择所谓比赛，不拼接分段。确认具体活动后查询：

```json
{"record_ref":"workout_log:123","activity_ref":"external_activity:456"}
```

也可直接查询已经得到的稳定活动引用：

```json
{"record_ref":"external_activity:456"}
```

直接活动查询的 `record=null`，`selected_activity` 是独立活动事实，不伪装成 WorkoutLog。指定活动必须属于认证用户，且在日志查询中还必须与该日志存在持久化关联。旧的 workout_log 调用仍返回原日志字段。

返回持久化的起始时间、时区、距离、计时/移动/经过时间、平均/最大心率、步频、步幅、触地时间、垂直振幅/比、功率、爬升与卡路里；字段缺失保持 null，列出 missing_fields。未请求 Garmin，也不保证所有设备已同步这些字段。

分段只来自选定活动，保留原 lap index、距离、时间、心率、步频和爬升。最多100段。`segments_complete` 仅代表存储的 laps 是否全部返回，**不是 Garmin 同步完整，也不保证覆盖整场比赛**。lap 不一定是一公里。可比较时返回 `segment_distance_consistent`，距离矛盾记录在 fact_issues，不补造缺失分段。

日志总距离与关联活动距离矛盾时保留两种来源，返回 LOG_ACTIVITY_DISTANCE_MISMATCH，不改数据库。截断或缺少距离时不虚构完整加总校验。

## 恢复趋势：复用 get_recovery_trend

```json
{"start_date":"2026-07-01","end_date":"2026-07-09"}
```

支持明确起止日期或旧的 days 参数，最多28天、不允许未来日期。返回每日 HRV、睡眠、静息心率、Body Battery、压力、主观疲劳、酸痛、腿部感觉、来源与同步时间。

仍要求独立 `mcp:recovery:read` 授权，无该权限时在查询数据库前拒绝。恢复缺失不填0，不计算新恢复评分或虚构 HRV 个人基线。同步元数据只投影本用户 Garmin 连接的最近尝试、最近成功时间和安全状态；原始错误码、凭据不返回。失败不会覆盖旧数值，历史查询中的同步状态指当前连接状态，不是当日同步的历史证明。

无法确定缺失原因时返回 NOT_RECORDED_OR_NOT_SYNCED，不将其说成设备必然不支持。主观感受缺失也不归咎于设备同步失败。

## 安全与部署边界

- 未新增数据库字段或表，无新增结构迁移。
- 仅授权用户可读取自己的活动、分段和恢复。没有 user_id 工具参数。
- 不导出 GPS、原始 payload、访问令牌、原始错误、活动标题、训练笔记和健康自由文本。
- 不新增日志/Trace 正文或真实数据 Fixture。公开评测仅使用虚构训练。
- 工具定义变化后，连接侧需要重新发现 Schema；服务端代码更新不会自动更新已经建立的客户端工具缓存。
- 本轮不合并 master、不推送、不部署，真实比赛及真实账号端到端验收尚未执行。
