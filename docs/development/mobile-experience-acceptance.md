# Core Experience 移动端适配验收

日期：2026-11-06。当前分支 `codex/admin-console-mvp`，保留此前全部未提交修改。本轮仅调整前端与测试，不操作生产库、不上传或部署、不自动提交或推送。

## 发现的问题

此前的宽度媒体查询只解决了部分排列，并不等于完成手机交互。真实问题包括：同步历史/活动和管理列表仍以宽表为主；引导步骤和操作区不够明确；聊天区560px最小高度超过横屏及低高度窗口；移动端Enter与中文输入法确认存在误发风险；弹窗45%外边距与固定宽度在小屏下不合理；手机没有可见的管理控制台入口。

## 本次修改

- 首次引导：三步进度标识，手机纵向选择卡片、设备操作和底部操作；保持跳过、继续、账号独立恢复，不自动连接设备或应用计划。
- 共用布局：底部安全区与内容留白、44px触控操作、弹窗内部滚动和双按钮布局；保留输入缩放，16px输入字体；不使用body横向隐藏掩盖溢出。
- 同步：手机独立任务卡片和设备活动卡片，真实数量、状态、错误和已有取消/重试操作；桌面仍保留表格。自定义范围改为两个原生本地时间输入，按既有UTC请求协议提交；缺失/反向日期不发同步请求。
- 今日/计划/复盘：闭环入口触控尺寸、快捷入口排列、周选择控件和确认按钮纵排、小屏日期面板限制宽度。重要风险信息不因为手机布局而移除。
- Coach：页面按可视窗口高度计算，聊天内容单独滚动，输入框和底部导航不重叠；监听visualViewport.resize及窗口旋转。低高度时压缩头部与输入区，页面问题改为明确的“带入问题”按钮，仍不自动发送。手机Enter换行、点击发送；桌面Enter发送、Shift+Enter换行；输入法组合态不发送。
- 手机历史会话继续使用抽屉，正文长单词/引用不会撑宽；桌面会话列表保持独立。
- 管理后台：用户、审计及模型档位换为移动卡片；配置表单单列、分页可换行、发布与权限弹窗适配；保留确认与管理员校验。后台手机导航置顶，跑者设置菜单仅管理员显示后台入口。
- 边缘返回手势只接管24px左边缘，避开输入框、按钮、表格和横向分段控件，避免编辑或选择范围时误离开。

## 验证

浏览器使用Edge/Playwright与合成API，未连接真实训练账号、Garmin或模型。覆盖320×640、360×740、390×844、430×932、768×1024、740×390横屏、1440×1000桌面。

- 跑者端每个尺寸覆盖7条页面路径以及有计划的今日页，共56个页面场景；另逐尺寸验证手机引导三步、长对话滚动、Enter不发请求、发送按钮不被导航遮挡、历史抽屉、同步卡片、无效日期不发请求。
- 管理端每个尺寸覆盖登录与概览、用户、AI、审计四页；手机权限弹窗不超宽、取消发布不发写请求、用户/审计卡片可见。
- 最初发现横屏发送按钮遮挡，修复低高度布局后复测通过。额外对320/390/740宽度复测今日日期弹层边界。
- 全量前端Vitest：155 passed，30 files；Typecheck通过；统一生产构建通过，仍有既有的大bundle警告。
- `git diff --check`通过。一次Vitest启动因Windows临时配置文件EPERM失败，重新执行后完整通过，不把首次失败当作通过。

截图与构建输出均在仓库外私有目录。运行脚本：`tools/core_experience_smoke.cjs`、`tools/admin_console_smoke.cjs`；支持通过`UI_VIEWPORTS_JSON`指定上述尺寸。

## 限制与人工验收

这是桌面浏览器的尺寸与交互验证，不是真机Safari/Android验收。刘海安全区采用env()与viewport-fit；系统键盘、浏览器地址栏伸缩、iOS回弹和中文输入法仍建议真机核对，不能将监听visualViewport等同于已经验证所有系统键盘行为。

人工检查：首次引导逐步前进/返回；同步页滑动、范围输入和任务按钮；聊天打开历史、输入中文、键盘弹出/收起和转横屏；后台搜索、编辑权限、取消发布；刷新后确认服务端权限与会话状态不变化。

本轮无需数据库迁移。未触发任何真实同步、配置发布或正式计划修改。
