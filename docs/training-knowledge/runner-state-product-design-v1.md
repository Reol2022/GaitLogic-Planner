# 跑者状态展示与历史快照产品设计 v1

> 对应版本：GaitLogic v0.10.3-C
> C1：当前跑者状态展示
> C2：历史状态快照设计与实现

## 1. 设计背景

v0.10.3-A 已建立统一、按需计算的跑者状态快照；v0.10.3-B 已建立可配置、可解释、确定性的跑量趋势、训练一致性和训练压力信号推断。当前接口能够回答“发生了什么”和“为什么得到该判断”，但原始字段主要面向开发者，普通跑者缺少一个结论优先、证据可展开的产品界面。

v0.10.3-C 将状态模型转化为可理解、可检查、可复盘的正式产品能力。C1 只展示当前状态；C2 才讨论历史保存和变化对比。两者必须分阶段实施，不能为了展示当前状态提前引入持久化负担。

## 2. C1 当前状态展示目标

C1 新增页面路由 `/runner-state`，页面名称为“训练状态”。页面基于当前登录用户的 `GET /api/runner-state/current` 响应展示：

- 综合摘要；
- 跑量趋势；
- 训练一致性；
- 疲劳信号；
- 训练阶段；
- 风险提示；
- 最近 7 天和 28 天核心指标；
- Evidence、未参与信号和规则集版本；
- 数据质量与当前限制。

C1 不保存快照，不新增写接口，不写数据库，不创建迁移，不生成或修改训练计划，不调用大语言模型。

## 3. C2 历史快照边界

C2 才设计并实现历史状态快照，包括快照保存时机、幂等性、规则版本追踪、历史列表、日期对比、保留周期、隐私策略和迁移方案。C1 不出现历史趋势、历史对比或“保存本次状态”按钮，也不预建空表或占位写接口。

## 4. 产品展示原则

1. 结论优先，Evidence 可展开；第一屏先回答“我最近的训练状态怎么样”。
2. 不创建新的综合分数，不在前端重算后端推断。
3. 不只依赖颜色；状态同时提供图标、标签、文案和说明。
4. 避免制造焦虑，不使用“危险”“即将受伤”“过度训练”等诊断式表达。
5. `UNKNOWN` 是正常业务状态，不是系统错误。
6. 缺失值显示“暂无数据”，真实数值 0 显示 0。
7. 普通模式突出可理解结论；内部 Reason Code 放在高级详情。
8. `evidence_coverage` 统一称为“证据覆盖程度”，不得称为准确率、置信概率或模型可信度。

## 5. 页面信息架构

页面按以下顺序组织：

1. 页面头部：名称、数据截止日期、最近计算时间、刷新按钮、非医疗说明入口；
2. 综合摘要；
3. 四张核心状态卡片；
4. 非空风险提示；
5. 最近 7 天和 28 天核心指标；
6. 各状态可展开的 Evidence 与高级详情；
7. 数据质量与 limitations。

入口至少出现在移动端“我的”页面和训练统计页面。移动端底部导航保持原有五项，不新增主栏目。

## 6. 综合摘要设计

摘要使用集中维护的确定性模板，根据后端已返回的状态组合选择文案，不调用大语言模型，也不读取 fatigue score 重新判断状态。

- 稳定：标题“近期训练整体较稳定”，说明跑量接近基线、执行稳定且未发现明显压力信号。
- 有变化：标题“近期训练状态出现一些变化”，提醒结合体感和计划执行复核。
- 压力增加：标题“近期训练压力有所增加”，提醒检查恢复和后续安排。
- 数据不足：标题“当前数据不足，暂无法完整判断”，引导继续记录训练、RPE 和计划完成情况。

摘要不是新的状态算法，只是已有状态的产品文案组合。

## 7. 四类核心状态卡片

### 7.1 跑量趋势

- `DECREASING`：下降
- `STABLE`：稳定
- `INCREASING`：增长
- `SPIKING`：明显增长
- `UNKNOWN`：暂无法判断

展示最近 7 天跑量、此前 21 天周均跑量和变化比例。该卡片只展示 `volume_trend`，不得写成综合训练负荷趋势。

### 7.2 训练一致性

- `LOW`：近期训练执行波动较大
- `MODERATE`：近期训练执行较稳定
- `HIGH`：近期训练执行稳定
- `UNKNOWN`：暂无法判断

同时展示判断依据：`PLAN_COMPLETION` 为“依据计划完成情况”，`ACTIVITY_REGULARITY` 为“依据训练频率稳定性”。

### 7.3 疲劳信号

- `NORMAL`：暂未发现明显压力信号
- `ELEVATED`：训练压力信号有所增加
- `HIGH`：多项训练压力信号同时出现
- `UNKNOWN`：数据不足，暂无法判断

第一屏不展示 fatigue score。前端不得根据 score 修改状态。

### 7.4 训练阶段

- `BASE`：基础期
- `BUILD`：建设期
- `SPECIFIC`：专项期
- `PEAK`：峰值期
- `TAPER`：减量期
- `RACE`：比赛期
- `RECOVERY`：恢复期
- `UNKNOWN`：未设置

阶段未设置是正常状态，不显示错误提示。

## 8. 风险提示区域

仅在 `risk_flags` 非空时展示，排序为 `ATTENTION`、`WARNING`、`INFO`。每项包括中文标题、后端 message、建议检查项、建议动作类型和可展开 Evidence。

页面可以提供“查看训练计划”和“查看最近训练”入口，但不得提供自动修改训练计划按钮，也不得在前端根据指标自行生成风险标记。

## 9. 最近 7 天和 28 天指标

最近 7 天展示：总跑量、总训练时长、训练次数、高强度次数、平均 RPE、计划完成率。

最近 28 天展示：总跑量、周均跑量、训练次数、活跃 7 日桶数量、关键课次数、高强度距离比例、计划完成率。

单位和精度使用统一格式化函数。空值与真实 0 必须区分。

## 10. Evidence 展示

Evidence 放在状态卡片或风险项的折叠区域中，展示指标名称、实际值、比较窗口、阈值、单位、数据来源和是否参与判断。长字段允许换行，不横向撑破页面。

Reason Code 默认不突出，只在“高级详情”展示；规则集版本在判断依据底部展示。

## 11. skipped signals 展示

未参与信号单独列出中文名称，并说明对应数据不足，因此没有参与本次判断。它们不是风险标记，也不表示训练状态异常。

## 12. 数据质量展示

数据质量必须分项展示：数据完整度、7/28 天有效训练数量、距离覆盖情况、时长覆盖情况、RPE 覆盖率、心率覆盖率、计划数据情况和 limitations。完整度分数只描述数据覆盖，不描述状态判断准确率。

## 13. UNKNOWN 策略

当推断证据不足时，页面继续显示基础指标、缺失项、未参与信号和数据限制。`UNKNOWN` 使用中性图标、标签和说明，不使用错误页、危险色或失败措辞。只有 API 请求本身失败时才进入错误状态。

## 14. 非医疗化文案

页面用于训练管理辅助，不构成医疗诊断、伤病判断或治疗建议。允许使用“建议结合体感检查恢复情况”“建议复核后续训练安排”等保守表达；禁止宣称用户已受伤、即将受伤、处于危险状态或必须停止训练。

## 15. 刷新机制

刷新按钮重新请求 `GET /api/runner-state/current`。当前状态 GET 不写数据库，刷新不保存快照。加载期间按钮禁用以避免重复请求；初次失败显示可理解的错误页；已有成功结果时刷新失败保留旧结果，并给出非阻断提示。

## 16. 当前状态与历史快照的区别

当前状态是请求时按现有数据和规则即时计算的结果，刷新后可能随训练记录变化。历史快照是某个时间点被持久化、可追溯的状态记录。C1 只有当前状态；不能把浏览器缓存或页面旧结果称为历史快照。

## 17. 历史快照概念设计

C2 的概念范围包括：快照日期、生成时间、规则集版本、基础指标、推断结果、Evidence 摘要、数据质量、去重键和保留策略。具体表结构、写入触发、API 和迁移必须在 C2 单独评审后实现，C1 不预设实现细节。

## 18. 隐私安全

页面只读取当前认证用户，不接受任意 user ID。响应和测试不得包含邮箱、手机号、Garmin Token、API Key、数据库密码、真实身份映射或未脱敏训练记录。视觉验收使用完全虚构快照，不写生产数据库。

## 19. 开源边界

公开产品仓库可以包含页面、通用组件、状态文案映射、格式化工具、虚构 Fixture、测试和技术文档。真实用户截图、真实状态快照、访谈反馈、竞赛展示脚本、私有演示账号和竞赛评测数据留在私有竞赛仓库。

## 20. 验收标准

- `/runner-state` 可从“我的”和训练统计进入；
- 只调用当前状态 GET，没有状态写请求；
- 四类状态、UNKNOWN、风险、Evidence 和数据质量展示正确；
- 第一屏不显示 fatigue score；
- Reason Code 仅在高级详情；
- 证据覆盖程度术语准确；
- 刷新失败不清空旧数据；
- 桌面、平板、移动和窄屏无横向溢出；
- 单元测试、构建、C1 类型检查和可运行后端测试通过；
- 没有数据库迁移、大模型调用、自动计划修改和真实用户数据。

## 21. 实施顺序

1. 恢复并确认产品设计；
2. 建立与真实 API 对应的前端类型；
3. 集中实现状态映射、摘要模板和格式化；
4. 实现页面组件、路由和入口；
5. 完成空值、错误、刷新和响应式处理；
6. 使用虚构数据完成单元与视觉验收；
7. 完成技术文档、安全检查和回归；
8. C1 验收可提交后，再单独启动 C2 设计与实现。
