# 跑者状态历史趋势与详情展示 v1

> 对应版本：GaitLogic v0.10.3-C2.2  
> 性质：公开产品能力；所有示例均为完全虚构数据。

## 1. 目标与边界

C2.2 将 C2.1 的不可变快照转换为可查询、可比较的历史界面。它不改变状态推断规则、快照表、序列化、哈希或去重规则，也不创建迁移。历史内容用于训练复盘，不是医疗诊断，不会自动修改训练计划。

## 2. 页面结构

页面继续使用 `/runner-state`，默认显示“当前状态”。用户首次切换到“历史趋势”后才加载历史数据，切回当前状态时保留已加载的历史缓存。历史区按以下顺序展示：

1. 时间范围选择；
2. 历史摘要；
3. 跑量趋势；
4. 分类状态时间线；
5. 风险事件；
6. 数据质量变化；
7. 原始快照列表。

不新增底部导航项目，也不新增独立历史主路由。

## 3. 刷新与保存

“刷新状态”只调用 `GET /api/runner-state/current`，重新按现有数据计算当前状态，不写数据库。“保存今日状态”只调用 `POST /api/runner-state/snapshots`，请求体为空对象，身份、触发方式、版本、payload 和哈希全部由后端确定。

创建成功显示“今日训练状态已保存”；重复结果显示“当前状态与最近保存记录一致，无需重复保存”，重复不是错误。保存期间按钮不可重复点击。失败时保留当前状态。历史区已经加载时，保存成功会重新加载当前历史范围；尚未进入历史区时不会提前请求历史接口。

## 4. Timeline API

```http
GET /api/runner-state/snapshots/timeline?range=28d
```

`range` 支持 `28d`、`12w`、`6m`，默认 `28d`。服务端以 Asia/Shanghai 的业务日期计算：

- `28d`：截止日及前 27 个自然日；
- `12w`：截止日及前 83 个自然日；
- `6m`：截止日向前推 6 个日历月。

前端只提交范围标识，展示后端返回的 `start_date` 与 `end_date`，不使用浏览器日期反推边界。

Timeline 只查询当前认证用户。每个 `data_cutoff_date` 保留一条记录，选择顺序为 `created_at DESC, id DESC`，最终按日期升序返回。`total_snapshots` 是范围内原始记录数，`days_with_snapshots` 是去重后的日期数。

响应不包含 `user_id`、`payload_hash` 或完整 `snapshot_payload`。距离、状态等字段优先读取快照表摘要列；只存在于 payload 的 RPE、心率覆盖率与风险明细通过一次批量 JSON 字段查询取得，避免逐条详情查询和 N+1。Timeline 不调用当前状态服务、不重新推断、不写数据库。

## 5. 历史摘要

摘要由确定性模板生成，显示范围、有记录天数、快照总数、最近快照日期、最近保存时间、最近跑量趋势、最近疲劳信号与存在风险提示的日期数。不生成健康分、风险概率、状态准确率或大模型总结。

## 6. 跑量趋势

图表复用项目已有 ECharts，展示：

- 最近 7 天跑量 `distance_7d_km`；
- 最近 28 天周均跑量 `distance_28d_weekly_average_km`，由后端基于完整 28 天摘要除以 4 后返回。

缺失值保持 `null`，ECharts 配置 `connectNulls: false`，既不补零也不跨缺口连接。悬浮提示展示真实日期和值。组件同时提供可横向浏览的数据表，避免只能通过图形读取数据；移动端使用稀疏刻度和横向滚动容器。

## 7. 分类状态时间线

时间线逐日展示 `volume_trend`、`training_consistency` 与 `fatigue_state`，复用 C1 的中文映射。状态改变节点突出，连续相同节点仍保留但弱化。UNKNOWN 使用中性样式。分类值不映射为数字，也不绘制连续折线。

## 8. 风险事件

Timeline 一次性返回保存时的风险标记最小展示信息。界面显示日期、中文标题、严重程度、保存时的说明和详情入口。多个日期出现同一提示时仍逐项呈现，只表述“该提示在多个保存日期重复出现”，不解释为持续伤病风险。

## 9. 数据质量

数据质量区统一显示：

- 数据完整度；
- 证据覆盖程度；
- RPE 数据覆盖率；
- 心率数据覆盖率。

缺失覆盖率显示“暂无数据”，不会显示为 0。以上均是数据覆盖情况，不是判断准确率、模型置信度或风险概率。

## 10. 原始快照列表与详情

原始列表继续使用 `GET /api/runner-state/snapshots`，使用 Timeline 返回的日期范围和 `limit/offset` 分页。列表保留同日全部不同快照，显示截止日期、保存时间、触发方式、三个状态、风险数和规则版本，不加载完整 payload。

详情使用 `GET /api/runner-state/snapshots/{snapshot_id}`，桌面端使用抽屉，窄屏使用全宽抽屉。详情直接展示保存时的 payload，并复用 C1 的摘要、状态卡片、指标、风险、Evidence、skipped signals、数据质量和 limitations 组件。界面明确提示：

> 这是当时保存的训练状态，不会根据当前训练数据重新计算。

详情不调用 current API。关闭详情时取消未完成请求并释放详情状态。规则版本和快照结构版本始终来自该历史记录。

触发方式的集中映射为：MANUAL（手动保存）、GARMIN_SYNC（Garmin同步）、DAILY（每日快照）、PLAN_ADJUSTMENT（计划调整）、SYSTEM（系统记录）。后四项仅为数据兼容映射，不表示 C2.2 已启用相应触发器。

## 11. 空状态、错误与竞态

无记录是正常状态，页面提示“还没有训练状态记录”，并提供返回当前状态入口，不会自动 POST。

当前状态、保存、Timeline、列表和详情分别维护加载与错误状态。Timeline 或列表失败时保留已有成功内容；保存失败不清空当前状态；详情失败停止 loading 并给出明确提示。范围请求与详情请求均使用 AbortController 和请求序号，旧响应不能覆盖新响应。

## 12. 移动端

在 680px 以下，范围按钮使用等宽触摸区域，信息卡改单列或紧凑双列；图表容器允许横向浏览；风险事件改单列。详情在 520px 以下使用全宽抽屉，元数据改单列。移动端底部导航仍保持原有五项。

## 13. 当前限制

- C2.2 只展示已经保存的离散快照，不代表连续监测；
- 同日 Timeline 只展示最后一条，但原始列表保留全部记录；
- 没有快照的日期不会插值；
- 缺失的跑量、RPE 或心率不会补零；
- 不提供竞技能力曲线、医疗风险预测、跨用户比较、删除或修改；
- 不启用 Garmin、每日或计划调整自动快照。
