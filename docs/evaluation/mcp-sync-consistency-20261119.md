### 已核查但不能认定为本次根因

- 当前 Garmin 使用带 offset 的分页读取和 UTC 查询窗口；已有跨午夜、时区和分页合成测试。本轮没有获取实时 Garmin 原始列表，不能证明上游在首次查询时已经提供了全部活动，也不能排除上游延迟。
- 现有同步逐活动使用 savepoint，外层提交失败回滚；关联活动后按全部有效关联重算。新增合成回归确认“先一条、再补另一条、重复同步”的聚合稳定性，不证明历史每一次距离变化都是错误。
- 无计划活动可以生成未计划日志。待处理或待确认活动仍不能擅自归到某堂课；现在旧式与分页 MCP 查询均暴露 `unresolved_activity_count` 和 `UNRESOLVED_ACTIVITIES`，说明汇总未包含它们。
- 既有增量游标不是本次 Smart Sync 窗口的直接依据：自动查询使用滚动重叠窗口，定期扩大补偿窗口。没有证据表明某个游标跳过了这次活动。

## 输出契约与兼容性

- 六个 MCP 工具名称、输入参数、OAuth scope 与 Resource Binding 不变。
- `job_id` 保持“当前匹配 scope 的活跃任务”语义。终态 ID 请读取 `last_job.job_id`，其他 scope 阻塞时读取 `blocking_job`；不可把后者当作本次训练任务。
- 回执只包含受控状态、数量、时间和低基数错误类别，不公开 `safe_error_message` 或原始错误。零新增/更新不等于恢复数据未改变；只对 activities-only 成功定义 `SUCCEEDED_NO_ACTIVITY_CHANGES`。
- `last_success_by_scope` 是成功抓取/处理水位，`facts_read_at` 是本次读取起点，`as_of` 是查询日期。水位不保证 Garmin 上游已经最终完整。
- `details_complete` 仍是当前存储结果的列表完整性，不代表上游同步完整。待确认活动通过独立数量和问题项报告，不偷偷补入总跑量。
- Runner State 的 LOW 继续表示既有训练规则风险；新鲜度无法确认时为部分评估，不是医学恢复许可。基础 MCP 权限不因此获得健康指标值。
- 无表结构变更，无生产迁移；前端仅补齐兼容响应类型，未新增工作台。
